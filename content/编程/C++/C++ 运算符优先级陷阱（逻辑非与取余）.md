# C++ 运算符优先级陷阱：! 与 %

> 来源：洛谷 P5716（输入年份和月份，输出该月天数）的调试案例——闰年判断永远失败。

## 问题代码（第 14 行）

```cpp
if(((!year%4)&&(year%100))||(!year%400))
```

想写的是 `!(year%4)`（year 能被 4 整除），但 C++ 中**逻辑非 `!` 的优先级高于取余 `%`**，表达式实际被解析为：

```cpp
(((!year) % 4) && (year % 100)) || ((!year) % 400)
```

即先算 `!year`，再算 `%4` / `%400`，与预期完全相反。

## 实际运行结果

对于任何非零年份（题目中年份一定大于 0）：

- `!year` 恒等于 0
- `0 % 4 == 0` 且 `0 % 400 == 0`（布尔值 false）
- 所以 `(!year%4)&&(year%100)` 恒为 false
- `(!year%400)` 也恒为 false

**结论**：整个条件永远为 false，任何年份都会走 else 分支输出 28，永远判断不出闰年。（例如输入 `2000 2`，正确应为 29，但程序输出 28。）

## 修改建议

1. 加括号，把取余括起来再取非：

```cpp
if( ( !(year%4) && (year%100) ) || !(year%400) )
```

2. **更推荐**：显式用 `== 0` 比较，不依赖优先级记忆：

```cpp
if( (year%4==0 && year%100!=0) || year%400==0 )
```

## 同类 bug（第 26 行）

```cpp
!month%2 ? cout<<"30"<<endl : cout<<"31"<<endl;
```

同样是 `!` 优先级高于 `%`，被解析成 `(!month)%2`，恒为 0（false），所以 7 月以前除 2 月外永远输出 31（4 月、6 月会错）。也需加括号写成 `!(month%2)`。

## 其他小问题（与闰年无关，但会 WA）

- 第 16 行 `cout<<year<<endl;` 会多输出一个年份，题目只要求输出天数，应删除
- 输出值要与题目要求的格式完全一致（一个整数）

## 经验总结

- 逻辑非 `!` 是**一元运算符**，优先级高于 `%` 等算术运算符
- 判断整除时，显式写 `x % n == 0` 比 `!(x % n)` 更安全、可读性更好
